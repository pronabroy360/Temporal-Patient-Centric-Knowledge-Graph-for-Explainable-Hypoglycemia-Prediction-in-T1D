# Loop canonicalization specification

Status: proposed release-specific transformation contract, 10 September 2026. It follows the [raw chronology audit](loop_release_audit.md) and [upload-linkage audit](loop_upload_linkage_audit.md). No raw record has been removed.

## Design principle

Canonicalization must remove only demonstrably identical re-exports. It must not use source-row order, upload time, or a later correction to decide what a predictor could have known. Retain all source record IDs and parent-upload IDs as provenance.

The source-adjacent profile found these same participant/UTC-time record pairs:

| Modality | Exact-key repeats | Conflicting same-time records | Rule |
|---|---:|---:|---|
| CGM | 6,214,818 | 888,918 | Collapse exact repeats; flag conflicting readings as ambiguous and exclude their timestamps from the primary CGM grid until a development-frozen resolution rule is justified |
| Basal | 86,741 | 53,387 | Collapse exact repeats; retain differing records because concurrent/superseded pump states require source-specific interpretation |
| Bolus | 60,256 | 3,682 | Collapse exact repeats; retain differing records as separate candidate deliveries or planned/delivered variants |
| Food | 12,187 | 2,154 | Collapse exact repeats; retain differing carbohydrate entries as distinct reported versions until a versioning rule is supported |
| Exercise | 2,849 | 675 | Collapse exact repeats; retain differing records |

These are lower bounds: the profile tests source-adjacent records only. A participant-sorted audit must quantify nonadjacent duplicates before final counts are reported.

## Canonical keys

All keys include `PtID` and UTC occurrence time. Preserve original units and raw values in provenance before normalization.

| Modality | Exact-repeat key | Normalized event |
|---|---|---|
| CGM | `RecordType`, `CGMVal`, `Units` | Retain only `RecordType=CGM`; convert mmol/L to mg/dL after range checks |
| Basal | `BasalType`, `Duration`, `ExpectedDuration`, `Percnt`, `Rate`, `SuprBasalType`, `SuprDuration`, `SuprRate` | Basal interval; duration is milliseconds and rate is U/hour |
| Bolus | `BolusType`, normal/extended delivered and expected amounts, delivered and expected durations | Insulin event; Tidepool duration is milliseconds |
| Food | `CarbsNet`, `CarbUnits` | Meal/carbohydrate event; preserve zero separately from missing |
| Exercise | name, distance/value unit, duration/value unit, energy/value unit, reported intensity | Exercise event after per-row unit conversion |

The stable representative of an exact group is the record with the lowest source `RecID`; all other source record IDs remain attached as duplicates. This is a deterministic provenance choice, not an availability-time choice.

## Primary-window safety rules

1. Sort by participant and UTC occurrence time before constructing windows.
2. Do not use `UploadUTCDtTm` as availability time; the linkage audit failed that gate.
3. Exclude calibration rows from CGM targets and inputs.
4. For conflicting CGM values at the same timestamp, exclude that timestamp and every candidate window needing it for history, recovery, target, episode confirmation, or grid alignment. Report the resulting exclusions.
5. Preserve conflicting non-CGM records as distinct events. Do not merge them by time alone.
6. Configure auxiliary-event delays only after canonicalization; apply the same delayed-event membership to graph and sequence comparators.
7. Keep raw data immutable. Write only aggregate reports and, when storage permits, partitioned derived outputs outside the raw release directory.

## Implementation constraint

The Loop raw release is larger than the free workspace capacity for a second full materialized copy. The implementation must therefore use participant-hashed streaming partitions or an approved external analysis volume; do not produce a full duplicate export in this workspace. A small synthetic fixture should test each key and conflict rule before any patient-level derived data are written.

The identifier-free evidence is [audit/loop_adjacent_duplicate_profile.json](../audit/loop_adjacent_duplicate_profile.json), generated by `scripts/profile_loop_adjacent_duplicates.py`.
