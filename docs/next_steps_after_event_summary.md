# Next research steps after the recorded-event summary result

Status date: 15 September 2026.

Update, 2 October: the residual and sequence pilots have since run. Follow the
[current controlled neural specification](loop_controlled_neural_experiments.md)
for the next campaign; the ordered plan below is retained as development history.

## Current evidence

The data and CGM benchmark foundation is ready. The corrected five-fold
development CGM logistic reference has participant-macro AP 0.446938 and
pooled Brier 0.021590 over 652 participants and 44,028,064 windows. The first
fourteen-feature recorded-event summary model performed worse on outer-0
validation: AP 0.425768 versus 0.457055 for matched CGM logistic. The paired
event-minus-CGM AP difference was −0.031288 with a 95% participant-bootstrap
interval of [−0.037799, −0.025438].

This result rules out advancing that summary model unchanged. It does not
answer whether individual event timing or typed relations help. The next work
must distinguish loss caused by event compression or model optimization from
a genuine lack of incremental recorded-event signal.

The 183-person final holdout remains excluded from model fitting, predictive
scoring, calibration, threshold selection, and architecture decisions. It has
already contributed aggregate data-quality and coverage counts, so describe it
as predictively unevaluated rather than wholly unseen.

## Step 1 — canonical event cache

Build one protected cache from Loop basal, bolus and food tables so subsequent
models never apply different deduplication, units, timestamps or participant
membership. Preserve record-level event instances for sequence and graph work;
do not cache only the failed summaries.

Each retained record needs: protected participant ID, stable protected event
ID, UTC occurrence time, modality and subtype, permitted numeric values and
units, missing-value flags, same-time conflict state, exact-repeat provenance,
and the event-contract version. Preserve raw source fields privately when
allowed, while exposing only aggregate audit output.

The initial modeling contract remains conservative:

- use `(t−120 minutes,t]` and no event after the prediction time;
- use normal bolus amount only until extended-delivery availability is proven;
- treat basal rate as a reported pump state, not delivered insulin;
- retain unsupported or missing carbohydrate records as presence with unknown
  grams;
- preserve distinct non-CGM records rather than merging them by timestamp;
- label availability as assumed immediate occurrence-time replay because Loop
  upload linkage did not provide a valid observed availability clock.

Cache completion requires reconciliation to the 652 development participants,
the model-manifest checksum, source row totals after canonicalization, and the
frozen CGM window identity hash. Record disk footprint and exact cache digests.

## Step 2 — frozen-CGM residual diagnostic

Keep each fold's selected CGM predictor fixed and learn only an event
contribution:

```text
logit(p) = logit(p_CGM) + delta_intercept + beta_event · event_features
```

At zero event coefficients this model reproduces the CGM predictor. This makes
the incremental event question cleaner than fitting all fourteen coefficients
again from scratch.

Use two prespecified variants:

1. **Presence/quality residual:** event presence/count, missingness, conflict
   and recency indicators without insulin/carbohydrate amounts.
2. **Value/timing residual:** the same indicators plus permitted basal rate,
   normal bolus and carbohydrate values.

Limit tuning on outer-0 validation to a small declared grid: L2 in
`{1e-4, 1e-3, 1e-2}` and epochs in `{1, 2}` with the existing learning-rate
schedule. Select by participant-macro AP, then lower Brier, then the simpler
model. Archive every candidate, including failures. This is diagnostic
development selection, not confirmatory inference.

Interpretation gate:

- improvement by the presence variant indicates capture/missingness signal;
- added improvement by values indicates incremental recorded clinical value;
- no improvement means the current summaries add no useful linear residual,
  but individual timing still requires Step 3;
- do not run residual candidates on development-test folds until one variant
  and its optimization are frozen.

## Step 3 — individual-event sequence comparator

Implement B4 from the decisive-experiment plan before implementing a graph.
Represent every admissible event separately with modality/subtype, permitted
value, unit/quality mask, and time since prediction. Preserve simultaneous
events and use masks rather than treating missing values as clinical zeros.
Use the same 120-minute history, participants, labels, and event membership as
the residual and future graph models.

Start with a small GRU event encoder and a CGM branch initialized from or
combined with the frozen CGM predictor. Predeclare maximum event count and
truncation direction: retain the most recent admissible events and report the
fraction truncated by modality and participant. Do not add patient-ID
embeddings. Run at least three fixed seeds once the architecture is frozen.

Compare on outer-0 validation:

- sequence versus frozen CGM: incremental recorded-event value;
- sequence versus event residual: value of individual timing/nonlinearity;
- sequence versus failed summary logistic: effect of representation;
- presence-only versus value-aware sequence: missingness/capture signal.

If no sequence variant improves on CGM and intervals exclude a useful gain,
the Loop data provide weak support for advancing a predictive KG claim. A
graph smoke test may still be reported as a negative controlled experiment,
but large architecture searches would not be justified.

## Steps 4–5 — freeze comparator and test relations

After sequence selection, freeze hidden size, number of layers, dropout,
optimizer, early-stopping rule, search budget, seeds and parameter count.
Implement the graph family with identical event nodes and attributes:

- **G0:** shared generic edge transform;
- **G1:** relation-specific transforms;
- **G2:** edge representation reconstructed from endpoint types and relative
  time rather than supplied semantic relation labels;
- **B4:** the frozen individual-event sequence comparator;
- **B2/B3:** gridded multimodal sequence and mask/time-aware sequence controls
  where the common inputs can be constructed honestly.

Match information first, then match capacity as closely as practical and
report exact parameter counts and training compute. A graph result supports a
relational inductive-bias claim only if G1 improves over B4, G0 and G2, the
paired participant interval supports the improvement, and the result is stable
across the three fixed seeds. G1 beating the failed summary model is not
evidence that relations help.

## Step 6 — availability and modality controls

Keep the eligible CGM windows and labels fixed. Replay meal records at imposed
delays of 0, 15, 30 and 60 minutes, followed by declared insulin-event delay
sensitivities if clinically meaningful. These are stress scenarios rather than
estimates of real reporting delay. Give every model the same admissible event
set and lag metadata.

Run modality analyses for insulin, meals, presence/missingness and values.
Describe them as input-ablation results. They do not prove causal clinical
effects. Retain the all-three-modality cohort only as a sensitivity analysis;
the primary comparison keeps all frozen windows with explicit missingness.

## Step 7 — metrics, calibration, alerts and explanations

For every frozen comparator report participant-macro AP with its defined
denominator, pooled AP, pooled and participant-macro Brier, calibration plots,
fold/seed variation, participant wins/losses and 2,000-draw paired participant
intervals. Preserve fixed predictions so metric corrections never require
retraining.

Select calibration and alert thresholds using validation participants only.
Then report confirmed-episode sensitivity, unmatched alerts per evaluable day,
precision and lead time on the applicable test group. Keep the any-low window
endpoint distinct from confirmed sustained episodes.

Run explanation deletion/retention, matched-random and stability tests only on
frozen models. Rebuild dependent features and topology after removing an event.
Computational fidelity does not establish clinical usefulness; clinician review
is required for a usability claim.

## Step 8 — final holdout gate

The final holdout can be predictively evaluated once, only after all of the
following are immutable and checksummed:

- input/event schema and canonicalization;
- models and parameter budgets;
- training, calibration and alert procedures;
- primary/secondary contrasts and practical-effect interpretation;
- seeds, bootstrap settings and multiplicity language;
- availability scenarios, explanation sample and failure analyses;
- code revision and environment.

Report the holdout regardless of direction. Do not tune, recalibrate or select
claims after viewing it. Any later adaptation becomes a separately labeled
experiment with a new untouched evaluation source.

## Step 9 — dataset roles and external replication

Loop remains the primary multimodal development cohort. After the model family
is frozen:

- use DCLP3 and DCLP5 for common-field insulin–CGM replication if their
  chronology and treatment-period gates pass;
- use AIDE as a CGM benchmark/context analysis, not meal-aware graph validation;
- use FLAIR for CGM or daily-treatment context, not individual-event relations;
- use OhioT1DM only if an eligible supervising advisor obtains access and a new
  release audit passes;
- call validation external only when it uses a distinct eligible cohort with a
  frozen common-field mapping.
